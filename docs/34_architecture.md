# Architecture

The framework deploys and validates dataspace environments through adapters, deployers, and validation suites.

## Main Areas

```text
main.py                         CLI and guided menu
framework/                      reusable validation, metrics, and reports
adapters/                       adapter-specific behavior
deployers/                      contracts, charts, and per-adapter deployers
validation/                     Newman, Playwright, and component validations
tests/                          Python unit tests
experiments/                    outputs generated by validation and metrics
```

Artifacts generated at runtime are kept out of Git whenever possible.

## Execution Model

The framework uses a six-level model:

```text
Level 1  cluster preparation
Level 2  common services
Level 3  dataspace runtime
Level 4  connectors
Level 5  optional components
Level 6  validation
```

`main.py` is the canonical entry point. It supports the guided menu and direct commands.

## Adapter Responsibility

An adapter knows how to interact with a specific dataspace implementation.

The current adapters are:

- `inesdata`;
- `edc`.

Adapters provide specific behavior such as connector URLs, credentials, bootstrap, data cleanup, and validation support.

## Deployer Responsibility

A deployer exposes the common deployment contract for an adapter.

Deployers live in:

```text
deployers/inesdata/
deployers/edc/
```

Shared infrastructure utilities live in:

```text
deployers/infrastructure/lib/
```

Shared charts and artifacts live in:

```text
deployers/shared/
```

## Validation Responsibility

Validation is centralized in level 6. It can run:

- prior cleanup of test data;
- Newman/Postman collections;
- UI tests with Playwright;
- component-specific validations;
- metrics collection.

The deployer context and the selected adapter determine which validations are enabled.
